# vipyemen — حزمة الإطلاق والمتاجر

## ملفات Android المتاحة

- `android/app/build/outputs/apk/debug/app-debug.apk`: نسخة اختبار موقعة بمفتاح debug.
- `android/app/build/outputs/bundle/release/app-release.aab`: حزمة AAB غير موقعة أو موقعة تلقائيًا حسب إعداد المشروع، ويجب التحقق منها قبل الرفع.
- مشروع `android/`: المصدر الكامل القابل للبناء عبر Gradle.

## متطلبات الإصدار النهائي

يجب على مالك التطبيق إنشاء keystore خاص باسمه وحفظه خارج المستودع. لا يجب إرسال المفتاح الخاص أو كلمة مروره عبر المحادثة أو وضعهما داخل ملف ZIP. بعد إعداد `key.properties` محليًا، يُبنى الإصدار النهائي باستخدام `./gradlew bundleRelease`، ثم يُتحقق من التوقيع قبل رفع AAB إلى Google Play Console.

## iOS

المجلد `ios/` هو مشروع Capacitor المصدر المطلوب لفتح المشروع في Xcode. إنشاء IPA وتوقيعه يتطلب macOS وXcode وحساب Apple Developer وشهادة توزيع وملف provisioning مملوكين للناشر. لا يمكن إنتاج IPA موقع صالح للتثبيت أو App Store من بيئة Linux دون هذه المتطلبات.

## الملكية والأمان

تبقى ملكية الحزمة واسم الحزمة والشهادات وحسابات المتاجر لدى صاحب التطبيق. يجب تفعيل HTTPS، وإضافة مصادقة حقيقية للوحة الإدارة، وعدم استخدام نسخة debug في الإنتاج.

## التحديث فوق النسخة السابقة

يستخدم التطبيق دائمًا `applicationId` الثابت `com.vipyemen.app`. يقوم سير الإصدار باشتقاق `versionCode` متزايد من وسم Git مثل `v1.0.4`، لذلك يتعرف Android وGoogle Play على الإصدار كترقية، ولا يحتاج المستخدم إلى حذف النسخة القديمة. تبقى بيانات التطبيق ما دام التوقيع الإنتاجي نفسه مستخدمًا. نسخة APK الموقعة بمفتاح مختلف لا يمكنها الترقية فوق نسخة موقعة بمفتاح آخر.

## أسرار GitHub Actions المطلوبة للإصدار الإنتاجي

للحصول على AAB موقع للنشر، تُضاف الأسرار التالية إلى إعدادات GitHub Actions باسمها الدقيق: `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD` و`ANDROID_KEY_ALIAS` و`ANDROID_KEY_PASSWORD`. يحول السير المفتاح مؤقتًا داخل بيئة البناء، ولا يحفظه في المستودع أو حزمة المصدر. إذا لم تُضف الأسرار، يبني السير AAB غير موقع لأغراض التحقق فقط، ولا يسمح ذلك بنشره تجاريًا قبل التوقيع.

## بوابة الجودة والإصدار

يجب أن يمر Pull Request بفحوصات TypeScript وVitest وVite وnpm audit وبناء Capacitor وGradle وExpo. كما يتحقق سير Android من `applicationId` و`versionName` وتوقيع APK وسلامة APK/AAB وSHA-256 قبل إنشاء Release. أما iOS فيُبنى على macOS داخل GitHub Actions للتحقق من مشروع Xcode دون تخزين شهادات Apple في المستودع؛ ويظل توقيع IPA النهائي مسؤولية حساب Apple Developer المملوك للناشر.

## التحقق من آخر إصدار منشور

عند توفر بيانات Google Play في مجموعة Codemagic، يستدعي سير Android أداة `google-play get-latest-build-number` للحزمة `com.vipyemen.app`، ويفشل قبل البناء إذا كان `versionCode` الجديد مساويًا أو أقل من الرقم المنشور. هذا يمنع نشر تحديث رجعي على Google Play. في التشغيل اليدوي دون بيانات Google Play، يبقى فحص وسوم Git فعالًا، ويجب على الناشر عدم تجاوز الرقم المنشور.
