# تقرير جاهزية ViP Yemen

## المنجز والمتحقق

تم نشر إصلاح التخطيط الرئيسي ومنع تراكب صورة المطور مع البطاقة عند المقاسات 390 و768 و820 و1280 بكسل، مع تحقق بصري موثق. أضيفت أدوات مالك محمية بخادم `ownerProcedure`، واستعلام واجهة `canManage` يخفي الأدوات عن المشرف غير المالك. يمكن للمالك رفع الأصول، إدارة البنرات والأيقونات، إنشاء وتحرير الأقسام وترتيبها، إنشاء الثيمات وتفعيلها، ومعاينة المسودات المصغرة.

تم إنشاء سجل نسخ `site_content_revisions` مع مسار استرجاع لا يحذف اللقطات السابقة. أضيفت اختبارات الصلاحيات والتحقق الهاتفي وحواجز الواجهة، ونجح TypeScript و17 اختبار Vitest وبناء الإنتاج.

## قياس الأداء الفعلي

تم تشغيل Lighthouse بتاريخ 28 أغسطس 2026. النتائج: Performance 55/100، Accessibility 95/100، Best Practices 82/100، SEO 92/100. لذلك لا يتم ادعاء تحقيق هدف Performance 95 بعد؛ التقرير الخام محفوظ في `lighthouse-2026-08-28.html` و`lighthouse-2026-08-28.json`، والتحسين التالي يجب أن يعالج حجم حزمة JavaScript وتقسيم تحميل لوحة الإدارة.

## فحوص CI والمسارات

يحتوي `quality.yml` الآن على فحوص TypeScript وVitest وVite وبناء Android وفحص سلامة الهوية، إضافة إلى smoke test يشغّل الخادم على منفذ مؤقت ويتحقق من استجابة المسارين `/` و`/admin`. لم يُشغّل هذا الملف على GitHub بعد لأن صلاحية GitHub App تمنع دفع ملفات workflows.

## المتطلبات الخارجية غير المكتملة

ملف `quality.yml` جاهز محليًا لفحوص الويب وCapacitor Android وسلامة الهوية، لكنه لم يُدفع إلى GitHub لأن صلاحية GitHub App الحالية ترفض إنشاء أو تحديث ملفات `.github/workflows` لغياب `workflows` permission. بعد منح هذه الصلاحية يمكن دفع الملف وتشغيله.

لا يمكن إثبات تثبيت Android فوق نسخة سابقة دون جهاز/محاكي وإصدار سابق مثبت في هذه البيئة؛ لذلك يقتصر CI على فحص versionCode وبناء الحزمة، بينما يتطلب اختبار بقاء البيانات تشغيل ترقية على جهاز اختبار. كما أن أرشفة iOS النهائية تتطلب macOS/Codemagic وشهادات Apple. تفعيل OTP الفعلي يتطلب مزود SMS أو WhatsApp Business ومفاتيح إعداد لا ينبغي وضعها في المصدر.
